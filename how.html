04 How a real report gets made

Many ways in. A decision out.

No new silo and no power-spy. Intune, RMM, and agent-based ingest are all available. Intune-heavy or SCCM-heavy shops get a path that respects what they already run. Four steps, with the honest limits printed on each one.

  1. 1

    Ingest →

    Intune / Graph when that is the system of record. RMM export or scripted pull when ConnectWise, Ninja, Datto, or similar already owns the box. Thin GlowOps agent when there is no MDM — inventory only, HTTPS, per-business enrollment key. SCCM / ConfigMgr-friendly feeds when the estate is still ConfigMgr-first. CSV if you just need a pilot. One-click deploy to Intune, an RMM, or any PC, packaged for that company only.

  2. 2

    Enrich →

    Match the model to a manufacturer PCF or to Boavizta’s open compilation. If the exact sheet does not exist, say so and use a documented fallback. Do not average the internet and call it science.

  3. 3

    Decide →

    Rules first. Machine learning only after the rules have been wrong in public often enough to deserve it. Security and a dead motherboard still win. Carbon does not ask you to keep a machine that cannot take the current OS.

  4. 4

    Report ✓

    One GLOW Op Report per client. Portfolio view for the MSP. PDF and CSV. The MSP’s logo, if they want their name on the joke.

What is already public

Boavizta’s environmental-footprint-data repository is the open pile of manufacturer PCFs; their API looks up a model. Intune can push a power policy and, on Surface, estimate emissions. Warranty-and-refresh packs for MSPs plan a calendar.

Haul-away

Physical haul-away is a partner. Someone else with a certification takes the dead ones.
