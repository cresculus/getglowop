Data & connectors

Resources

What GlowOps collects, which connector supplies it, Graph permissions required, and what lands in the dashboard store. Product path is Intune + Entra app registration — Graph sync pulls devices. No manual paste required for customers.

1 · Intune / Entra connector

Primary. Create an Entra app registration in the customer tenant → admin consent → GlowOps Graph sync reads managedDevices → same inventory schema → score → report. That replaces the old paste-JSON “Ingest” tab.

Entra app permissions (application)

  • DeviceManagementManagedDevices.Read.All — managed device inventory (required)
  • DeviceManagementConfiguration.Read.All — optional policy context
  • Reports.Read.All — optional bulk exports
  • Endpoint Analytics / battery Graph APIs — only when licensed

Admin consent required. Start with managed-devices read only; expand least-privilege.

2 · Optional Intune health probe

Not a resident agent. Deployed as Intune Proactive Remediation / platform script when the tenant lacks Endpoint Analytics.

  • Reads battery WMI locally on the device
  • Posts a small health patch (merge by serial / Azure AD device id)
  • Auth: business enrollment key or Intune-side attribute path

3 · Windows agent / collector (lab)

Local WMI/CIM one-shot (or GlowOpsAgent.exe join). Sideburned for Intune customers; useful in lab and non-Intune fleets.

Permissions on the PC

  • Standard user can collect most inventory
  • Elevation improves BitLocker / some battery / predict-failure classes
  • Join uses partner enrollment key + password (expiring, join-only)

4 · Stored in the dashboard

Per-business (tenant) SQLite today → Postgres/RLS later. Scored inventory powers Fleet, Dashboard, Properties, CSV, MCP.

Field groupExamples

Also stored

  • Ingest / sync events (who/what/count/time)
  • Partner sessions + MCP API keys (hashed)
  • Device join keys (hashed password, TTL, revoke)
  • Agent heartbeats (optional)
